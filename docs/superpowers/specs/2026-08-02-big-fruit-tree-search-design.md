# 大果樹搜尋首頁視覺優化設計

## 目標

將目前職缺搜尋頁改造成「大果樹」品牌首頁。頁面的唯一主要工作仍是搜尋職缺，不增加導覽入口、活動廣告或內容型首頁區塊。視覺採用已確認的 B「新鮮市集」方向：明亮、親切、有活力，保留自然與收穫意象，但避免像競賽宣傳頁。

## 品牌與文案

- 產品名稱：大果樹。
- 主標題：「找工作，今天就有好結果。」
- 說明文字：「選好條件、輸入關鍵字，把適合的職缺摘回家。」
- 品牌語氣親切、直接，不強調 AI、隊名或競賽。
- 隊名與比賽資訊如需保留，只能以低視覺權重放在 footer。
- 頁面 `<title>` 與 description 改以「大果樹」及職缺搜尋為主。

## 視覺系統

### 色彩

- 樹葉綠 `#244A30`：文字、邊框、焦點與主要品牌識別。
- 果實橘 `#F1A52A`：搜尋按鈕與品牌果實。
- 陽光黃 `#F4B937`：hero 頂部色帶與少量強調。
- 新芽綠 `#B9D7B4`：搜尋框硬陰影與輔助裝飾。
- 米白 `#FFFDF4`：首頁背景。
- 純白 `#FFFFFF`：搜尋框與結果卡片。

色彩不使用大面積漸層。主要美感來自清楚色塊、粗邊框、柔和圓角與少量偏移陰影。

### 字體

- 標題使用圓潤、厚實的繁體中文無襯線字體堆疊，呈現友善與活力。
- 內文及控制項沿用易讀的系統繁中字體堆疊。
- 技術資訊如 Request ID 維持低權重，不參與主要視覺。

### 品牌標記

使用「果」字圓形標記搭配偏移的新芽綠陰影，與「大果樹」文字形成簡單 wordmark。第一版不新增外部插畫或圖片資產，避免首頁變成活動 banner；後續可獨立設計正式 logo。

## 搜尋區結構

桌機版將所有條件整合為同一個白色搜尋元件，順序如下：

1. 工作多選條件。
2. 區域多選條件。
3. 搜尋日期。
4. 關鍵字輸入框，佔據最多水平空間。
5. 「搜尋職缺」按鈕。

既有的 `MultiSelectChecklist` 功能、搜尋能力及鍵盤操作完整保留。搜尋日期仍保留既有預設值與送出格式。視覺改造不得改變 API request shape。

搜尋框下方可顯示少量熱門關鍵字膠囊；第一版只作為填入關鍵字的捷徑，不新增 API 或推薦服務。若現有內容沒有可信的熱門來源，使用靜態示例並明確視為 UI shortcut。

## 響應式行為

- 桌機：五個區段在單一水平搜尋元件內。
- 平板：條件保持可辨識；空間不足時允許換成兩列。
- 手機：工作與區域為第一列兩欄，日期為單獨欄位或第二列，關鍵字及搜尋按鈕各自佔滿一列。
- 無論斷點如何變化，關鍵字與送出動作必須保持最強視覺權重。
- 最小支援寬度為 320px，不得產生水平捲動。

## 搜尋結果狀態

送出搜尋後沿用現有資料流程：呼叫搜尋 API，再依結果 ID 取得職缺詳細資料。此次工作只改變視覺與前端呈現，不變更 API contract。

- 載入：搜尋元件維持在頁面上方，按鈕顯示明確進度且禁止重複送出。
- 成功：hero 垂直空間縮短，結果列表緊接搜尋區；卡片使用白底、綠色標籤與低裝飾密度。
- 部分失敗：保留現有成功結果與失敗筆數提示。
- 全部失敗、空結果與驗證錯誤：保留現有訊息語意，調整為大果樹品牌色和直接可行的指引。
- Request ID 保留在錯誤或結果區底部，維持可追蹤性。

## 無障礙與互動

- 保留語意化 `form`、label、button、status 與 alert。
- 所有控制項提供清楚的 `:focus-visible` 狀態。
- 色彩對比需符合 WCAG AA；不可只靠顏色表達選取或錯誤狀態。
- hover 使用輕微位移或陰影變化；遵守 `prefers-reduced-motion`。
- 多選選單在鍵盤、觸控與窄螢幕上皆可完整使用。

## 元件邊界

- `+page.svelte`：頁面品牌、搜尋表單組合、搜尋狀態與結果版面。
- `MultiSelectChecklist.svelte`：保留既有選取邏輯，只調整與新搜尋元件一致的視覺介面。
- `search.ts`：不修改 request、response 驗證與資料流程，除非實作時發現純呈現需要的型別調整。
- `filter-options.json`：不改資料內容。

## 驗證標準

- 現有 Web 單元測試全部通過。
- `pnpm --dir apps/web check`、test 與 build 通過。
- 以桌機及 320px 手機寬度確認搜尋元件無溢出。
- 實際確認工作、區域、日期及關鍵字均可操作並送出原有 request shape。
- 搜尋成功、載入、空結果、部分失敗及錯誤狀態皆有可讀畫面。
- 首屏不再出現原隊名或比賽名稱；若保留，僅出現在 footer。

## 不在本次範圍

- API、搜尋排序、資料庫或 runtime 修改。
- 新增帳號、收藏、履歷或導覽功能。
- 建立完整品牌識別系統或正式插畫資產。
- 將首頁擴充為活動或內容入口網站。
